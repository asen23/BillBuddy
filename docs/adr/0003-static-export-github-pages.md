# Static export, deployed to GitHub Pages by GitHub Actions

BillBuddy ships as a fully static Next.js export (`output: "export"`) and deploys to GitHub Pages from `main` via `.github/workflows/deploy.yml`, which builds with `actions/configure-pages` (supplying the `/BillBuddy` base path) and publishes `out/` with the official Pages actions. This follows from ADR-0001: with no backend and all state in the browser, nothing needs a Node runtime, so the cheapest host that can serve files is enough — and the repo already lives on GitHub. The base path is injected only at deploy time (`BASE_PATH`), so local dev and the e2e suite keep running at the origin root. Considered and rejected: a Node host (Vercel/Netlify) running `next start` (works, but adds a platform and a runtime for zero server-side work); the `gh-pages` branch method (branch-based Pages runs Jekyll, which would need a `.nojekyll` shim and publishes build output into git history). Trade-off accepted: static export removes `next start`, so the e2e suite serves `out/` with `serve` instead — ADR-0002's suite still runs against a production build, now the exact artifact Pages publishes. Revisit if BillBuddy ever needs a server.
