# Client-only, BYO-key Gemini integration

BillBuddy has no backend: receipt extraction calls Gemini directly from the browser using the visitor's own API key, stored in their browser's localStorage (previously under the poorly named key `secret`, renamed to `billbuddy.apiKey`). We deliberately chose this over a serverless proxy holding a shared key, because BillBuddy is a personal tool: a proxy would introduce a secret to manage, abuse surface to protect, and hosting cost, while a client-side BYO key means the key never leaves the user's own browser and there is nothing to operate. Considered and rejected: a Vercel server route with an environment-held key (needs abuse protection the app doesn't warrant yet). The trade-off accepted: every user must supply their own key, and on any deployed copy the key sits in localStorage in plaintext — revisit if BillBuddy ever becomes multi-user or the key becomes shared.
