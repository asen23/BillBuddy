# End-to-end tests only, with Gemini mocked at the network layer

Verification for BillBuddy is a Playwright end-to-end suite running against a production build, with `generativelanguage.googleapis.com` intercepted and served fixture responses — there is deliberately no unit-test layer, even though `lib/split.ts` is a pure module. Reasons: the app is three screens deep and the split math feeds directly into one user path, so end-to-end tests protect the thing that matters with the least infrastructure; mocking at the network boundary means no test-only branches in production code; and the suite runs key-free and deterministically in CI. Considered and rejected: vitest unit tests for the math (more precise failure localization, but a second framework and a second layer for ~50 lines of covered logic). Trade-off accepted: math bugs surface as failing flows with less pinpointed output, and the suite is slower than unit tests — revisit if the domain logic grows beyond the current split rules.
